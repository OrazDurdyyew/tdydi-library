# i18n-add-key

Добавляет ключ перевода во все 3 файла локали Nuxt i18n.

## Когда использовать

- "добавь перевод для ..."
- "новый ключ i18n: ..."
- "локализуй кнопку/заголовок ..."
- при создании новой страницы или компонента

## Файлы

- `/frontend/locales/tm.json` (туркменский, основной)
- `/frontend/locales/ru.json` (русский)
- `/frontend/locales/en.json` (английский)

## Структура ключей

Иерархическая, по смысловым группам. Префиксы:
- `common.*` — общее (кнопки, действия): `common.save`, `common.cancel`, `common.delete`
- `nav.*` — навигация и меню
- `home.*` — главная страница
- `book.*` — страница книги
- `section.*` — страница раздела
- `admin.{module}.*` — админка (`admin.books.create`, `admin.sections.delete_confirm`)
- `errors.*` — сообщения об ошибках
- `validation.*` — сообщения валидации форм
- `seo.*` — meta-теги (если общие)

## Что сделать

1. Спросить у пользователя:
   - Ключ (с префиксом, например `admin.books.upload_button`)
   - Текст на 3 языках. Если пользователь даёт только один — попросить остальные или предложить варианты.
2. Открыть три файла локали.
3. Добавить ключ во все три файла в правильное место в иерархии (alphabetically внутри секции).
4. Не дублировать существующие ключи — проверить grep по всем 3 файлам.

## Соглашения

- Ключи — snake_case (`upload_button`, не `uploadButton`)
- Тексты — без trailing dots для коротких надписей (кнопки, лейблы); с точкой для предложений
- Если в тексте есть переменные — используем `{var}` синтаксис: `"items_count": "Найдено {count} книг"`
- Пословные переводы избегать — лучше адаптировать смысл

## После добавления

- Использовать в шаблоне: `{{ $t('admin.books.upload_button') }}`
- В composables/store: `const { t } = useI18n(); t('...')`
- При большом количестве ключей — упомянуть что можно использовать `defineI18nLocale` для namespace
