# ТЗ: Электронная библиотека (платформа для ВУЗов)

## Контекст

Проект — новый. Цель: создать **универсальную платформу электронной библиотеки**, которую можно развернуть для любого ВУЗа (изначально — Институт экономики и управления, в дальнейшем — другие вузы). Каждый ВУЗ получает **отдельный деплой** на свой сервер. Вся настройка под брендинг ВУЗа (логотип, фавикон, цвета через дизайн-токены, название, контент) выполняется **через админку** без изменения кода.

**Защита кода**: исходный код остаётся у разработчика. Другие ВУЗы получают только Docker-образы из приватного registry — `docker-compose.yml` + `.env` на сервере ВУЗа, исходники недоступны.

**Изменения в этой ревизии (по обратной связи института):**
- Иерархическое меню сайта: разделы и подразделы (2 уровня), управляемые из админки. Заменяют плоский список "кафедр".
- Раздел "Газеты" переименован в **"Периодические издания"** и объединяет газеты + журналы в одной сущности.
- Введена система прав: админам можно выдать доступ только на определённые разделы для управления книгами.

Базовый функционал: каталог книг (PDF/EPUB), онлайн-читалка, раздел периодических изданий, новости института, виртуальные подборки, FAQ, статичные страницы. Сайт работает на трёх языках, основной — туркменский. Регистрация пользователей не требуется: контент открыт всем, авторизация — только для администраторов.

---

## 1. Целевая аудитория и роли

| Роль | Доступ | Возможности |
|---|---|---|
| **Гость (читатель)** | Без регистрации | Просмотр каталога, чтение онлайн, скачивание (если разрешено), поиск, фильтры, переключение языка, закладки через браузер |
| **Суперадмин** | Логин/пароль | Полный CRUD всего контента, управление разделами, админами, настройки сайта, статистика |
| **Контент-менеджер** | Логин/пароль | Управление книгами **только в назначенных разделах** (добавлять, редактировать, удалять); статистика по своим разделам |

---

## 2. Распространение платформы между ВУЗами

- **Один деплой = один ВУЗ.** Каждый ВУЗ — отдельный инстанс на своём сервере.
- **Исходный код не передаётся**:
  - Разработчик собирает Docker-образы (`api`, `frontend`) и пушит в **приватный Docker Registry** (например, GitHub Container Registry, Docker Hub Private, Yandex Container Registry, или self-hosted)
  - ВУЗ получает: `docker-compose.yml`, `.env.example`, инструкцию по развёртыванию, доступ к registry (логин/пароль)
  - На сервере ВУЗа: `docker compose pull && docker compose up -d`
- Обновления распространяются через push новой версии образа в registry + `docker compose pull` на стороне ВУЗа.
- Все настройки под конкретный ВУЗ задаются через админку.
- При первом запуске админка открывает мастер первичной настройки: загрузить логотип, выбрать цвета, задать название.

## 3. Функциональные требования — публичный сайт

### 3.1. Динамическое меню сайта (НОВОЕ)
- Главное меню формируется **динамически** из таблицы `sections` (разделов).
- Поддерживается **2 уровня вложенности**: раздел → подраздел.
- Структура и порядок управляются из админки (drag-and-drop).
- **Поведение в меню**:
  - Если у раздела **нет подразделов** — пункт меню ведёт напрямую на страницу раздела (`/sections/{slug}`).
  - Если у раздела **есть подразделы** — при hover (на десктопе) или tap (на мобильном) открывается dropdown со списком подразделов. Клик по самому родительскому разделу также ведёт на его страницу — там показываются собственные книги раздела + список подразделов.
- Slug у разделов **глобально уникальные**, URL плоский: `/sections/{slug}` (упрощает SEO и переименование разделов).
- Пример из института: раздел "Кафедры" с подразделами "Кафедра экономики", "Кафедра языков", "Кафедра менеджмента" и т.д.

### 3.2. Страница раздела
- URL: `/sections/{slug}`
- Содержит:
  - Название и описание раздела (на 3 языках)
  - Изображение раздела
  - **Список книг, привязанных непосредственно к этому разделу**
  - **Если есть подразделы** — список карточек подразделов (с обложками и кратким описанием)
- Фильтры и сортировка для книг
- Хлебные крошки: Главная → Раздел (→ Подраздел, если открыт)

### 3.3. Главная страница
- **Баннер/слайдер** (управляется из админки): несколько слайдов с изображением, заголовком, подзаголовком, ссылкой
- **Раздел "Новинки"**: последние N добавленных книг
- **Настраиваемые блоки разделов**: админ выбирает, какие разделы (любого уровня) показывать на главной и в каком порядке. Каждый блок отображает обложку, название и несколько книг раздела с кнопкой "смотреть все".
- **Виртуальные подборки на главной**: например, "К экзамену", "Рекомендовано преподавателями"
- **Лента новостей института** (последние 3-5 публикаций)
- **Поиск** — заметная строка поиска в шапке

### 3.4. Каталог книг
- Группировка по **разделам** (с иерархией: раздел → подразделы)
- **Одна книга может быть привязана к нескольким разделам** (и/или подразделам) одновременно — M:N
- **Фильтры**: раздел/подраздел, год издания, автор, язык книги
- **Сортировка**: по дате добавления, названию, году, популярности
- Карточка книги: обложка, название, автор, год

### 3.5. Страница книги
- **Метаданные на одном языке книги** (а не на трёх): название, автор(ы), год, издательство, ISBN, кол-во страниц, **язык книги**, аннотация, обложка, теги
- Список разделов/подразделов, к которым книга привязана (с гиперссылками)
- **Онлайн-читалка** в браузере (PDF.js для PDF, epub.js для EPUB)
- **Закладка через localStorage**: автоматическое запоминание последней прочитанной страницы (без регистрации)
- **QR-код** на странице книги
- Кнопка "Скачать" (если в админке для книги стоит флаг "разрешить скачивание")
- Блок "Похожие книги" (по разделам/тегам)
- Счётчики просмотров и скачиваний

### 3.6. Раздел "Периодические издания" (ПЕРЕИМЕНОВАН И РАСШИРЕН)
Объединяет **газеты и журналы** в одну сущность с указанием типа.

- Список всех периодических изданий с фильтром по типу: "Все / Газеты / Журналы"
- Карточка издания: обложка, название, тип, краткое описание, периодичность
- **Страница издания**:
  - Описание издания
  - **Список выпусков** с пагинацией, отсортированных по дате
  - Архив по годам/месяцам
- **Страница выпуска**:
  - Обложка, дата, номер/том, аннотация выпуска
  - Просмотр онлайн (PDF.js)
  - Опциональное скачивание
- Поиск работает по названиям изданий и выпусков

### 3.7. Виртуальные подборки
- Тематические подборки книг ("К экзамену по микроэкономике", "Классики менеджмента")
- Отдельная страница подборки: описание + список книг
- Создаются и наполняются админом
- Могут отображаться на главной

### 3.8. Новости / блог института
- Список новостей с пагинацией
- Страница новости: заголовок, дата, автор, обложка, текст (WYSIWYG), галерея
- Метаданные на 3 языках

### 3.9. Статичные страницы (CMS)
- "О библиотеке", "Контакты", "Правила пользования"
- Управляются через WYSIWYG-редактор в админке
- Произвольное количество, добавляются админом
- Опционально добавляются в меню сайта (как отдельный пункт меню, не связанный с разделами)

### 3.10. FAQ
- Список вопрос-ответ, сгруппированный по категориям
- Управление через админку (CRUD)
- Поиск по FAQ

### 3.11. Поиск (PostgreSQL FTS + pg_trgm)
- **Без отдельного поискового сервиса** — используем встроенный полнотекстовый поиск PostgreSQL
- Расширения: `pg_trgm` (нечёткий поиск, опечатки), стандартный `tsvector`/`tsquery`
- Индексирует: книги (название, автор, аннотация, теги), периодические издания, новости, FAQ, статичные страницы
- Поддержка трёх языков через `to_tsvector('russian'/'simple', ...)` (для TM/EN — `simple` config + ILIKE/trigram fallback)
- GIN-индексы на `tsvector` колонках для скорости
- Раздельные результаты по типам контента
- Простой autocomplete через `pg_trgm` similarity

### 3.12. Мультиязычность интерфейса (i18n)
- Языки UI: **TM (по умолчанию), RU, EN**
- Переключатель языка в шапке
- На 3 языках: интерфейс, разделы (название и описание), баннеры, новости, статичные страницы, FAQ, виртуальные подборки, периодические издания, название института
- **Книги хранятся в одном языке** (поле `language`) — без перевода метаданных
- URL-структура: `/tm/...`, `/ru/...`, `/en/...`

### 3.13. Брендинг через дизайн-токены
Все настраиваемые параметры сайта хранятся в таблице `site_settings` и применяются как **CSS-переменные** на фронте. Настраиваемое в админке:
- Название института на 3 языках
- Логотип (светлый/тёмный), фавикон
- **Цветовые токены** (палитра shadcn-vue): `--primary`, `--secondary`, `--accent`, `--background`, `--foreground`, `--muted`, `--border`, `--ring` и т.д.
- Шрифт (выбор из набора Google Fonts)
- Контакты (адрес, телефон, email), соц. ссылки
- Текст футера на 3 языках

Изменения применяются без передеплоя.

### 3.14. Адаптивный дизайн
- Поддержка десктоп / планшет / мобильный
- Минимальная ширина: 320px
- На мобильных меню становится "гамбургером" с раскрывающимися подразделами

## 4. Функциональные требования — админ-панель

Админка реализована в том же Nuxt-проекте, что и публичный сайт, на маршрутах `/admin/*` и защищена через **глобальный middleware** (проверка JWT-токена). Неавторизованные пользователи редиректятся на `/admin/login`. Видимость разделов и доступные действия в админке зависят от прав текущего админа (см. 4.13).

### 4.1. Аутентификация
- Логин/пароль для админов, JWT-токен, refresh-токен
- Rate limiting на логин (защита от brute-force)
- **Без email-восстановления пароля** — сброс делает суперадмин вручную

### 4.2. Управление разделами и меню сайта (НОВОЕ — только суперадмин)
- **Древовидный CRUD разделов** (2 уровня: раздел → подраздел)
- Поля раздела: slug (уникальный), название (3 языка), описание (3 языка), изображение, parent_id (NULL для верхнего уровня), sort_order
- **Drag-and-drop** для:
  - Изменения порядка разделов в меню
  - Перемещения подраздела между родителями
- Подсчёт привязанных книг для каждого раздела (включая подразделы)
- Запрет на удаление раздела, если в нём есть книги/подразделы (или удаление с подтверждением и каскадом)

### 4.3. Управление книгами
- CRUD: создать, редактировать, удалить, скрыть/опубликовать
- **Загрузка файла PDF/EPUB без лимита размера** (chunked upload через tus.io или аналог)
- Загрузка обложки (или автогенерация из первой страницы PDF через `pdftoppm`)
- **Метаданные на одном языке**: название, аннотация, авторы (строкой), язык книги
- **Привязка к нескольким разделам или подразделам** (multi-select из tree-picker)
- Теги
- Флаги: "разрешить скачивание", "опубликовано"
- **Контент-менеджер видит и редактирует только книги в своих разделах** (см. 4.13)

### 4.4. Управление периодическими изданиями (только суперадмин)
- CRUD изданий: название (3 языка), тип (газета/журнал), обложка, описание (3 языка), периодичность
- CRUD выпусков: дата, номер/том, обложка выпуска, файл PDF, краткая аннотация (3 языка)
- Сортировка выпусков по дате
- Архив

### 4.5. Управление виртуальными подборками (только суперадмин)
- CRUD: название (3 языка), описание (3 языка), обложка
- Добавление/удаление книг в подборку
- Флаг "показывать на главной" + порядок

### 4.6. Управление новостями (только суперадмин)
- CRUD новостей с **WYSIWYG-редактором (TipTap, бесплатный MIT)**
- Заголовок, текст, обложка, галерея — на 3 языках
- Дата публикации, автор, статус (черновик/опубликовано)

### 4.7. Управление статичными страницами (только суперадмин)
- CRUD страниц: slug, заголовок, контент (WYSIWYG TipTap) — на 3 языках
- Флаг "добавить в меню" + позиция в меню (страницы добавляются как самостоятельные пункты меню рядом с разделами)

### 4.8. Управление FAQ (только суперадмин)
- CRUD категорий FAQ
- CRUD вопрос-ответ с привязкой к категории, на 3 языках
- Drag-and-drop сортировка

### 4.9. Управление главной страницей (только суперадмин)
- Слайдер: добавить/удалить/переупорядочить слайды
- Выбор разделов/подразделов для отображения на главной и их порядок
- Выбор подборок для отображения
- Настройка кол-ва книг в "Новинках"

### 4.10. Настройки сайта (брендинг — только суперадмин)
- Раздел "Settings" в админке
- Загрузка логотипа (светлый/тёмный), фавикона
- Color picker для всех CSS-токенов
- Live preview изменений
- Название института, контакты, футер, шрифт
- Сохранение → инвалидация кэша → применение на сайте

### 4.11. Статистика
- Дашборд: всего книг, скачиваний, просмотров за период
- Топ-10 популярных книг (по просмотрам и скачиваниям)
- Топ разделов по активности
- График активности по дням
- Экспорт CSV
- **Контент-менеджер видит статистику только по своим разделам**

### 4.12. Управление админами (только суперадмин)
- CRUD админов
- Назначение роли: **суперадмин** или **контент-менеджер**
- Для контент-менеджера: назначение списка разделов (`admin_section_permissions`), к которым он имеет доступ
- Возможность дать доступ ко "всем разделам" одним флагом (`all_sections = true`)
- Принудительный сброс пароля

### 4.13. Система прав (RBAC) (НОВОЕ)
- Две роли: **superadmin**, **content_manager**
- **superadmin** — полный доступ ко всему
- **content_manager**:
  - Видит в админке только разделы из таблицы `admin_section_permissions` (или все, если `all_sections = true`)
  - При создании книги — может выбрать только разрешённые разделы из tree-picker
  - При редактировании книги — может изменять только книги, у которых **все** разделы входят в разрешённые
  - Может удалять книги только из своих разделов
  - **Не имеет доступа** к: разделам (CRUD), периодике, новостям, FAQ, страницам, главной, настройкам сайта, управлению админами
- Проверка прав **на бэкенде** на каждый запрос (фронт только скрывает кнопки/пункты)

## 5. Технологический стек

### Frontend (один Nuxt-проект)
- **Nuxt 4** + **TypeScript** + **Vue 3** Composition API
- **Один проект** — публичный сайт + админка
  - `/`, `/sections/*`, `/books/*`, `/news`, `/periodicals/*` и т.д. — публичный сайт (SSR)
  - `/admin/*` — админка, защищена через **глобальный middleware** (`auth.global.ts`)
  - Разные layouts: `default` (публичный) и `admin`
  - Админ-страницы рендерятся в client-only режиме (через `definePageMeta({ ssr: false })`)
- **Pinia** — стейт-менеджмент
- **@nuxtjs/i18n** — интернационализация (TM/RU/EN)
- **TailwindCSS** + **shadcn-vue** — UI-компоненты (бесплатные)
- **TipTap** — WYSIWYG для админки (MIT)
- **PDF.js** — просмотр PDF
- **epub.js** — просмотр EPUB
- **qrcode** — генерация QR-кодов
- **vue-draggable-next** (или аналог) — drag-and-drop для управления порядком разделов, FAQ, слайдов

### Backend
- **Go** + **Fiber**
- **GORM** — ORM для PostgreSQL
- **golang-jwt/jwt** — JWT
- **golang-migrate** — миграции БД
- **validator** — валидация
- **tus** или собственный chunked upload — для больших файлов
- **pdftoppm** (системная утилита) — извлечение обложки из PDF
- **Middleware прав** в Go — проверяет роль и `admin_section_permissions` на каждом запросе к `/api/admin/*`

### Хранилище и инфраструктура
- **PostgreSQL 16** — основная БД. Расширения: `pg_trgm`, `unaccent`
- **Файловая система сервера** — хранение PDF/EPUB и обложек:
  - `/var/library/books/{book_id}/file.pdf`
  - `/var/library/books/{book_id}/cover.jpg`
  - `/var/library/periodicals/{issue_id}/file.pdf`
  - `/var/library/branding/logo.png`, `favicon.ico`
  - В БД хранится только относительный путь
  - Nginx раздаёт файлы через `X-Accel-Redirect`
- **Redis** (опционально) — кэш популярных запросов и счётчиков
- **Docker + Docker Compose** — деплой одной командой
- **Приватный Docker Registry** — для образов
- **Nginx** — reverse proxy, статика, отдача файлов

## 6. Модель данных (основные сущности)

```
admins
  id, username, password_hash, email
  role (enum: 'superadmin' | 'content_manager')
  all_sections (bool — для content_manager: доступ ко всем разделам)
  created_at

admin_section_permissions      // M:N: какие разделы доступны админу
  admin_id, section_id
  PRIMARY KEY (admin_id, section_id)
  (если у admin all_sections = true — записей не нужно, доступ ко всем)

site_settings                  // singleton, одна строка
```

## 7. Нефункциональные требования

- **Производительность**: TTFB на каталоге <500мс при 100 одновременных пользователях; поиск <300мс
- **Загрузка файлов без лимита**: chunked upload, прогресс-бар, возобновление при обрыве
- **Безопасность**:
  - HTTPS обязателен
  - Rate limiting на логин
  - CSRF-защита для админки
  - Sanitize загружаемых имён файлов, проверка типа по магическим байтам
  - Sanitize HTML из WYSIWYG (DOMPurify на бэке)
  - Bcrypt для паролей
  - Файлы хранятся вне веб-корня, отдаются через контроллер
  - **Авторизация на каждом запросе админки**: проверяется роль + права на конкретный раздел
  - Защита кода: образы только в приватном registry
- **SEO** (только для публичных страниц):
  - Nuxt 4 SSR
  - Meta-теги, OpenGraph, sitemap.xml на 3 языках, robots.txt
  - Чистые URL: `/ru/sections/economics`, `/ru/books/economics-101`
  - Админ-страницы исключены из индексации
- **Доступность**: семантический HTML, alt-теги, контраст по WCAG AA
- **Резервное копирование**: ежедневный `pg_dump` + rsync `/var/library/`; хранение 7 дневных + 4 недельных копий

## 8. Архитектура

```
[Browser]
   │  /             → SSR публичный сайт (Nuxt 4)
   │  /sections/*   → страницы разделов и подразделов
   │  /admin/*      → SPA админка (тот же Nuxt, middleware)
   ▼
[Nginx] reverse proxy + статика + X-Accel-Redirect для файлов
   │
   ▼
[Go API: Fiber]
   ├─ middleware: auth (JWT) → role/section permissions check
   ├─→ PostgreSQL (метаданные + FTS)
   ├─→ /var/library/ (PDF/EPUB)
   └─→ Redis (опционально)
```

**Endpoint меню**: `GET /api/menu` возвращает дерево разделов с подразделами + статичные страницы с `in_menu=true`. Кэшируется в Redis или в памяти, инвалидация при изменении разделов.

**Поток брендинга**: фронт GET `/api/site-settings` → CSS-переменные в `<head>` → shadcn-vue использует их.

**Поток скачивания**: браузер → Go (счётчик + проверка прав) → `X-Accel-Redirect` → Nginx отдаёт файл с диска.

**Защита админки**:
- Фронт: `middleware/auth.global.ts` для `/admin/*` (кроме `/admin/login`)
- Бэк: Go middleware на `/api/admin/*` проверяет JWT + роль; для операций с книгами проверяет `admin_section_permissions`

## 11. Критерии приёмки

- [ ] Платформа разворачивается на чистом сервере одной командой `docker compose up`
- [ ] При первом входе суперадмина запускается мастер первичной настройки
- [ ] Брендинг меняется через админку и применяется без передеплоя
- [ ] Фронт — один Nuxt-проект; `/admin/*` защищён через global middleware
- [ ] **Меню сайта формируется динамически из разделов**, поддерживает 2 уровня вложенности
- [ ] **При hover на разделе с подразделами открывается dropdown; клик ведёт на страницу раздела**
- [ ] **Раздел без подразделов открывается как страница со своими книгами по `/sections/{slug}`**
- [ ] **Книга может быть привязана к нескольким разделам и подразделам одновременно**
- [ ] Каталог фильтруется по разделу, году, автору, языку
- [ ] Метаданные книги хранятся на одном языке (язык книги)
- [ ] Загрузка PDF/EPUB без лимита размера (chunked upload с прогрессом)
- [ ] Книга открывается онлайн в PDF.js, читалка запоминает страницу через localStorage
- [ ] EPUB открывается в epub.js
- [ ] QR-код генерируется на странице книги
- [ ] Поиск через PostgreSQL FTS+pg_trgm покрывает книги, периодику, новости, FAQ
- [ ] **Раздел "Периодические издания" объединяет газеты и журналы; работает архив выпусков**
- [ ] Виртуальные подборки создаются и отображаются на главной
- [ ] Новости / статичные страницы / FAQ управляются на 3 языках через TipTap
- [ ] **Суперадмин может создать контент-менеджера и выдать ему доступ к выбранным разделам**
- [ ] **Контент-менеджер видит и редактирует только книги в назначенных разделах; удаление в своих разделах**
- [ ] Файлы хранятся в файловой системе, БД содержит только пути
- [ ] Скачивание идёт через Go (счётчик) → nginx (отдача) через X-Accel-Redirect
- [ ] Статистика показывает топ книг, топ разделов и скачивания (с учётом прав)
- [ ] Сайт корректно отображается на мобильных (320px+); меню становится гамбургером
- [ ] HTTPS настроен, админка защищена rate limiting
- [ ] Ежедневный бэкап БД и файлов настроен
- [ ] Docker-образы публикуются в приватный registry
