# CLAUDE.md

Контекст проекта для Claude. Подробное ТЗ — в [ТЗ.md](ТЗ.md).

## Что за проект

Универсальная платформа электронной библиотеки для ВУЗов. Каталог книг (PDF/EPUB) с онлайн-читалкой, периодические издания (газеты + журналы), новости, FAQ, статичные страницы. Первый клиент — Институт экономики и управления (Туркменистан). Платформа рассчитана на повторное развёртывание для других ВУЗов: один деплой = один ВУЗ.

**Защита кода**: исходники не передаются. ВУЗ получает только Docker-образы из приватного registry + `docker-compose.yml`.

**Статус**: greenfield. ТЗ утверждено. Начинаем MVP.

## Технологический стек

| Слой | Технология |
|---|---|
| Frontend | Nuxt 4 (TypeScript, Vue 3 Composition API), один проект для публичного сайта + админки |
| UI | TailwindCSS + shadcn-vue (цвета через CSS-переменные из БД) |
| WYSIWYG | TipTap (бесплатный, MIT) |
| i18n | @nuxtjs/i18n — TM (по умолчанию), RU, EN |
| Читалки | PDF.js (PDF), epub.js (EPUB) |
| State | Pinia |
| Backend | Go + Fiber |
| ORM | GORM |
| БД | PostgreSQL 16 (расширения `pg_trgm`, `unaccent`) |
| Поиск | PostgreSQL FTS + pg_trgm (без отдельного сервиса) |
| Файлы | Файловая система сервера (`/var/library/`), отдача через nginx `X-Accel-Redirect` |
| Загрузка | tus.io (chunked, без лимита размера) |
| Деплой | Docker Compose + приватный Docker Registry |
| Reverse proxy | Nginx |

**Решения с историей** (если возник соблазн их менять — сначала перечитай ТЗ):
- Файлы хранятся в файловой системе, **не** в БД и **не** в MinIO. В БД — только пути.
- Поиск — PostgreSQL FTS, **не** Meilisearch (исключено для упрощения деплоя).
- Фронт — один Nuxt-проект; `/admin/*` защищён через `auth.global.ts` middleware. Никаких двух отдельных приложений.
- Метаданные книги хранятся **в одном языке** (поле `language`). На 3 языках — UI и контент-таксономия (разделы, подборки, новости, FAQ, страницы).
- Без регистрации пользователей. Только админы логинятся.

## Ключевые доменные концепции

### Разделы (sections) — иерархическая навигация
- Древо из 2 уровней: раздел → подраздел. Глубже не делаем (`CHECK` в БД).
- Slug **глобально уникальный**. URL плоский: `/sections/{slug}` — для раздела любого уровня.
- Меню сайта строится динамически из endpoint `GET /api/menu`.
- Раздел без подразделов → клик ведёт на страницу с книгами.
- Раздел с подразделами → hover показывает dropdown; клик ведёт на страницу раздела (свои книги + карточки подразделов).
- Управляются drag-and-drop в админке (только суперадмин).

### Книги (books)
- Привязка к разделам — **M:N** через `book_sections` (одна книга может быть в нескольких разделах/подразделах).
- Метаданные (title, annotation, authors) — в одном языке (поле `language`).
- Файл хранится в `/var/library/books/{book_id}/file.pdf`, в БД только путь.
- Скачивание: Go проверяет права + инкрементит счётчик → отдаёт `X-Accel-Redirect` → nginx стримит файл с диска.
- Онлайн-чтение через PDF.js/epub.js. Закладка через `localStorage` (без регистрации).

### Периодические издания (periodicals)
- Одна сущность для газет и журналов, различаются полем `type ('newspaper' | 'magazine')`.
- Выпуски — отдельная таблица `periodical_issues` с датой, номером, файлом.
- Архив по годам/месяцам.

### Роли и права (RBAC)
- **superadmin** — полный доступ ко всему.
- **content_manager** — управляет **только книгами** в назначенных разделах:
  - `admin_section_permissions` (M:N) — какие разделы доступны
  - либо флаг `all_sections = true` (все разделы)
  - НЕ имеет доступа к: разделам, периодике, новостям, FAQ, страницам, главной, настройкам, другим админам
- Проверка прав **обязательно на бэкенде** на каждом запросе к `/api/admin/*`. Фронт только скрывает UI.

### Брендинг через дизайн-токены
- Таблица `site_settings` (singleton) хранит: название (3 языка), логотип, фавикон, цветовые токены shadcn (`primary`, `secondary`, `accent`, `background`, `foreground`, `muted`, `border`, `ring`), шрифт, контакты, соц. ссылки.
- На фронте `GET /api/site-settings` → CSS-переменные в `<style>:root { ... }</style>` → shadcn-vue компоненты используют их.
- Изменения применяются без передеплоя.

## Мультиязычность

- 3 языка: **TM (по умолчанию), RU, EN**.
- URL: `/tm/...`, `/ru/...`, `/en/...`.
- На 3 языках хранятся: интерфейс, разделы, баннеры, новости, страницы, FAQ, подборки, периодика, название института. Поля в БД: `name_tm`, `name_ru`, `name_en` и т.д.
- **Книги — на одном языке** (поле `language`). Никаких `book_translations`.

## Конвенции

- **Комментарии в коде**: только если объясняют *почему* (неочевидное решение, обход бага, бизнес-ограничение). Не описывать *что* — должно быть видно из имён.
- **Имена** — английские. Доменные термины следуют ТЗ (sections, periodicals, book_sections и т.д.).
- **Slug** генерируется из названия с транслитерацией. Уникальность проверяется на бэке.
- **Файлы** — никогда в БД. Только пути.
- **Загрузка** — chunked через tus.io. Не пытаться буферизовать большие файлы в памяти.
- **Безопасность**:
  - Bcrypt для паролей.
  - Rate limiting на `/api/auth/login`.
  - JWT в HttpOnly cookie (или Authorization header — выбрать при реализации auth).
  - Проверка магических байтов при загрузке файлов (не по расширению).
  - HTML из WYSIWYG санитайзить на бэке перед сохранением (DOMPurify-аналог для Go).
- **Бэкапы**: ежедневный `pg_dump` + rsync `/var/library/`. 7 дневных + 4 недельных копий.

## Этапы разработки

1. **MVP (этап 1)** — backend модели, JWT, CRUD разделов и книг, загрузка файлов, главная, страницы разделов и книги, читалка PDF, i18n UI, простой поиск (ILIKE), админка для книг/разделов/брендинга/прав.
2. **Этап 2** — слайдер, периодика, подборки, новости, страницы, FAQ, EPUB, FTS+pg_trgm, фильтры, QR-коды, закладки в читалке.
3. **Этап 3** — SEO (SSR, sitemap, meta), статистика с графиками, похожие книги, бэкапы, Docker-образы в приватный registry, документация по разворачиванию.
